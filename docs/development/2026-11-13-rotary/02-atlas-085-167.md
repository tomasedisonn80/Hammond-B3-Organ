## Implications for this independent rotary work

The assigned pages support a **separately identified nominal motion and
propagation module with synthetic numerical tests**. They do not close M5, M6
or measured M7. The current repository reports an active scanner numerical
track, including unresolved same-hertz accuracy, and a separate native
standalone track. This assignment has not rerun those reported tests. Neither
track should be overwritten or counted as rotary work.

The following contracts should be frozen before new implementation:

1. **Separate owners and coordinates.** Scanner angle, generator angle, horn
   angle and drum angle must not alias one state merely because all are rotary
   quantities. Horn and drum each own actual speed and angle. Their target
   commands, direction, angle origin and supported states belong to a named
   cabinet/control profile (p. 154). No constant in pp. 157-167 supplies Leslie
   speed or inertia.
2. **Preserve the sample timeline.** Motion continues through rendered silence
   and unrelated notes/presets. Zero-sample calls supply no elapsed mechanical
   time. Sample-rate preparation changes the step size without inventing a new
   angle. The default proposed suspended-host policy freezes processed-time
   state; any wall-clock extension needs a different reproducibility claim
   (pp. 105-108, 154, 166).
3. **Distinguish a target from physical motion.** A speed command is not a
   speed-state assignment or phase reset. Reversing or interrupting a command
   starts from the current state. An illustrative first-order or other motion
   law must identify its numerical model and proposed parameters; the existence
   of an exponential percussion surrogate does not make the same law measured
   Leslie mechanics (pp. 129, 135, 154).
4. **Declare the input boundary.** A two-branch acoustic processor must state
   what the horn and drum excitations contain, their units/scales, and which
   electrical, driver, radiation, propagation, cabinet, microphone and room
   contributions it owns. A delayed or filtered capture cannot silently receive
   that effect a second time. Existing dry output is normalized and unmeasured;
   wrapping it with rotary processing would not produce a calibrated acoustic
   pressure signal (pp. 91-96, 141-143, 147-150).
5. **Keep ordinary state compatible.** Existing 45 controls, old migrations,
   plugin UUIDs and dry arithmetic remain owned by their current contracts.
   A research module can first use a separate profile/probe without changing
   those public identities. Later integration needs append-only identifiers,
   explicit live-load behavior and a versioned migration. A musical patch does
   not include a delay-buffer checkpoint by implication (pp. 126, 151, 155).
6. **Do not infer STOP from a GUI.** Page 154 explicitly requires supported
   commands to follow the cabinet/control profile. A diagnostic fixed-angle
   mode can be defined for tests without claiming it is the stock cabinet's
   historical control position.
7. **Prepare immutable data and bounded storage.** Validation, coefficient
   generation, delay-buffer allocation, resource loading and retirement occur
   outside processing. Invalid preparation leaves the previous prepared model
   and running history usable. Each rejected command must have a declared
   failure-state policy (pp. 94-96, 106, 112, 118, 155-156).

This is architectural inference from the cited cross-cutting contracts. Detailed
rotary geometry, interpolation and radiation equations must be checked against
the separate readers of chapters 45-54 before they become implementation inputs.

## Suggested acceptance evidence before integration

| Gate | Proposed falsifiable check and boundary |
| --- | --- |
| Profile admission | Strict units, finite bounds, unique IDs and explicit evidence classes; malformed data leaves prior state unchanged. Test zero versus missing rather than substituting defaults silently (pp. 91-96). |
| Independent motion | Changing one rotor's target affects only its owned history. Compare each chosen nominal law to an independently derived trajectory, including interrupted acceleration, deceleration and direction conventions (pp. 87-90, 154). |
| Phase and time | Replay one absolute event stream with one-sample and varied block partitions; include silence, zero-sample calls, rate changes and unrelated registration events. Check speed and angle as well as audio (pp. 105-108, 126, 154). |
| Acoustic ownership | Fixed-rotor, known-excitation fixtures reveal exactly which delay, gain and response are applied. An explicitly equivalent preprocessed input must not receive duplicate processing (pp. 93, 96, 147). |
| Numerical convergence | Use an independent reference with fixed units, alignment and gain conventions. Declare interpolation, phase, spectral and latency budgets before grading. Do not tune normalization to hide a model mismatch (pp. 104, 107-108, 120). |
| Failure continuation | Exercise invalid profile/command data and capacity limits from nonzero history. Verify the promised old-state continuation and bounded behavior, not merely finite output (pp. 96, 118, 156). |
| Realtime scope | Instrument actual prepared process paths and identify what allocation/lock coverage was observed. A synthetic numerical pass cannot establish device deadlines or host behavior (pp. 106-108). |
| Physical admission | Retain actual cabinet/control identity, trajectories, geometry and synchronized captures. Hold out complete motion segments or revolutions and unseen conditions. Until then, report nominal engineering only (pp. 89-90, 95, 154, 167). |
