The [operator guide](INTERFACE_RUNBOOK.md) is the detailed user contract. F4/F5/F6 select Play/Rotary/Service; F7 toggles Flat. These view changes preserve sound controls and existing release ownership. A hidden Play control cannot receive a new click or edit from another workspace. Help, Audio and MIDI deliberately release UI holds. Save is explicit; closing the app does not save.

All four drawbar banks remain retained. On each manual, C cancels the route, C#–A selects one of nine fixed registrations, A# sounds adjustable bank A, and B sounds adjustable bank B. Edit A/B chooses which bank is edited independently of the sounding route. Cancel preserves bank memory and held-note history. Upper-B percussion eligibility remains explicit. The fixed selector is already implemented; the next M3 work concerns physical contacts, latches, loading and circuit evidence.

The writer emits `B3CONTROLS4`; readers for versions 1–3 remain. Snapshot freshness, applied versus desired controls and evidence availability remain distinct. Unknown physical quantities are shown as unavailable, not fabricated zero values. Rotary artwork is decorative and cabinet audio is not connected.

## Build and run from a usable checkout

The commands below are procedures for a fresh usable checkout, not commands executed after the workspace outage. Run them from the repository root. Use CMake/CTest 3.21 or newer, Python 3.10 or newer, Git, a C++20 compiler and a C compiler for SDL. Platform desktop/audio development packages are required for the backends you intend to test. The [MIDI setup guide](MIDI_UI_RUNBOOK.md#prerequisites-and-platform-backends) lists Linux ALSA, Windows WinMM and macOS CoreMIDI requirements.

Acquire the pinned SDL2 2.32.10 source into an absent path outside the repository. Its parent must exist. If that dependency already exists, use `--verify-existing ../SDL2` instead of acquiring again.

~~~sh
python3 tools/acquire_sdl2.py --destination ../SDL2
cmake -S . -B build-interface -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DHAMMOND_BUILD_STANDALONE=ON -DHAMMOND_SDL2_ROOT="$PWD/../SDL2" \
  -DHAMMOND_ENABLE_MIDI=OFF -DHAMMOND_BUILD_VST3=OFF
cmake --build build-interface --config Release --parallel 2
ctest --test-dir build-interface -C Release -N
ctest --test-dir build-interface -C Release --output-on-failure --no-tests=error \
  -R '^test_standalone_'
~~~

This builds the SDL keyboard/pointer application without physical MIDI. Synthetic replay remains available. Discover the selected configuration before interpreting its test count; a count from another checkpoint or build is not a substitute.

On Windows use `python` if that is the installed command and add `.exe` to executables. A multi-configuration build adds `Release/` before the executable. The examples use a POSIX shell and single-configuration paths. The [preset guide](PRESET_RUNBOOK.md) and [VST3 build guide](VST3_BUILD.md) retain complete alternative recipes. An ordinary SDK-free core build requires neither SDL, RtMidi nor the VST3 SDK.

For physical MIDI, acquire the pinned RtMidi 6.0.0 source into another absent external path and use a separate build. Existing dependencies use their verifier; do not edit or substitute dependency source to bypass identity checks.

~~~sh
python3 tools/acquire_rtmidi.py --destination ../rtmidi-6.0.0
cmake -S . -B build-interface-midi -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DHAMMOND_BUILD_STANDALONE=ON -DHAMMOND_SDL2_ROOT="$PWD/../SDL2" \
  -DHAMMOND_ENABLE_MIDI=ON -DHAMMOND_RTMIDI_ROOT="$PWD/../rtmidi-6.0.0" \
  -DHAMMOND_BUILD_VST3=OFF
cmake --build build-interface-midi --config Release --parallel 2
~~~

SDL audio/video and native MIDI are separate capabilities. Dummy SDL drivers do not bypass ALSA/CoreMIDI/WinMM discovery. Select a unique real MIDI input and distinct Upper/Lower/Pedal channels explicitly, then Apply. There is no automatic input connection. A retained discovery error remains historical evidence even after a successful recovery; No Input, Apply, Disconnect and Close remain usable.

Create an output directory and choose a writable state path:

~~~sh
cmake -E make_directory out
build-interface/apps/standalone/hammond_standalone \
  --state "$PWD/out/my-controls.b3controls" --workspace play
~~~

A missing state file starts the proposed audition setting: Upper B `888000000`, Lower B `008000000`, pedal mixtures `80`. It is not a factory preset. Startup requests 48 kHz and 512 frames from the default output; the request is not a measured latency. Use Audio to select and Apply a real output configuration, and Save explicitly to create the state file.

The installed payload can be moved as a unit. Use new destination names so these commands do not overwrite an existing installation:

~~~sh
cmake --install build-interface --config Release --component Standalone \
  --prefix "$PWD/out/interface-install"
cmake -E rename "$PWD/out/interface-install" "$PWD/out/interface-moved"
"$PWD/out/interface-moved/bin/hammond_standalone" \
  --state "$PWD/out/my-controls.b3controls" --workspace service --flat
~~~

The [installation guide](STANDALONE_INSTALL.md) defines the complete payload. Earlier MIDI-on/off qualification recorded 19 and 15 files, including six installed guides. A later guide refresh preserved executable bytes. That evidence does not claim a new post-outage installation was built.

A bounded dummy-driver inspection can create a diagnostic file and bitmap without selecting physical hardware:

~~~sh
SDL_AUDIODRIVER=dummy SDL_VIDEODRIVER=dummy \
  build-interface/apps/standalone/hammond_standalone \
  --state "$PWD/out/unused-controls.b3controls" --workspace service --flat \
  --width 960 --height 700 --smoke-ms 600 \
  --screenshot "$PWD/out/service.bmp" --diagnostics "$PWD/out/service.json"
~~~

Use new output names and retain the actual executable, source, dependency, driver and diagnostic identities. This procedure does not qualify physical audio, MIDI, display DPI or pointer capture.
