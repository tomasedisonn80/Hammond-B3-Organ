## Concrete implications for the next M9 interface slice

1. **Use the requested visual reference with live semantic controls.** The
   reference's material, composition and illumination can guide the renderer.
   Drawbar footages, values, preset selection and held-note feedback must still
   come from the actual copied state. Page 53 explicitly requires labels from the
   semantic control table rather than labels baked into generated imagery.
   Source art and actual executable captures need separate provenance.

2. **Expose an inspectable explanation of the current signal path.** A bounded,
   read-only service/inspection surface can show current model identity,
   implemented versus unimplemented stages, source/terminal distinctions and
   evidence status without waiting for physical recordings (pp15–16,34,43,61).
   Its entries should use stable IDs and explicit unknowns. A cabinet picture
   alone must not imply that the active output passes through a Leslie model.

3. **Treat display mode as presentation state.** Switching player/inspection
   views, hiding a cabinet, resizing, disabling animation or closing the editor
   must preserve controls, held owners, ongoing generator phase, contact and
   percussion histories (pp34,40,46,54). Keep view preferences outside the
   current musical snapshot and state-format meaning. Rendering and asset
   loading must not enter the audio callback (pp12,34,46).

4. **Preserve the correct playable inventory through any composition change.**
   There are 122 manual playing keys, 25 pedals, separate preset octaves and all
   38 retained drawbar values. The original four-bank requirement remains even
   when only the edited bank appears (p49). The verified order is
   `16, 5⅓, 8, 4, 2⅔, 2, 1⅗, 1⅓, 1` feet, with
   `brown, brown, white, white, black, white, black, black, white` caps. A visually
   depressed preset key must agree with the applied route; inactive-bank edits
   must not change a fixed registration (pp50,54).

5. **Define useful acceptance before implementation.** Compare native captures
   at the reference size and supported compact sizes; verify labels, placement,
   clipping, readable values, focus and hit targets. Independently exercise mode
   changes during held chords and pending controls, then inspect applied state
   and saved controls. Check keyboard operation without animation (p54). Retain
   exact input/source/build identities and unresolved visual differences; these
   are interface checks, not hardware or acoustic qualification (pp13,18,36).

## Limits and traps to retain in handoff

- Page 50's exclusive enum is a proposed initial software behavior. The same page
  notes that physical multiple latching is possible and C is a momentary
  mechanical cancel. Do not call the current exclusive selector a complete
  physical latch-network model.
- The key-travel example on p38 belongs to one 1967 C-3. It cannot establish a
  universal B-3 geometry, and animated depression cannot prove contact closure.
- A rendered cabinet/rotor or a future family selector must not invent audio
  connectivity, independent measurements or a production-ready 122/147 profile.
- Model identity, source/calibration status and unknowns survive save/reload;
  successful visual reconstruction cannot turn nominal sound into measured sound.
- The 319-callout companion inventory claim on p36 and other referenced companion
  files are atlas claims. This reading does not recover absent files or verify
  their underlying evidence.
- This review supports dependency-ready UI engineering while the independent
  scanner, organ electronics, Leslie, calibration and physical-acquisition tracks
