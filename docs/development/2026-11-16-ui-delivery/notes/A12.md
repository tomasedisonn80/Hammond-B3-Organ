## Delivered behavior

The new Python standard-library checker reads this session's `assignments.json`
and accepted notes. Its default progress mode permits an incomplete session;
`--strict` requires all IDs A01–A60 accepted in their ten six-worker waves.
Both modes return JSON and exit 0 for valid records, 1 for a validation failure.
There is no `--repo` option: the script locates the session beside itself.

It checks exact version/session/base/count metadata, unique IDs and canonical
agent names, ID-to-wave correspondence, nonempty task descriptions and the
two supported states. Every note path must be exactly `notes/Axx.md`, preventing
absolute paths, traversal, cross-session references and accidental note reuse.
Accepted records require a lowercase SHA-256 matching the original UTF-8 bytes.
Running records may lack a note and cannot carry an accepted-note hash.

Accepted notes must contain at least 200 stripped characters and 40 words.
This is only a minimum text-size check; repeated words or poor reasoning still
need root's substantive review. The checker rejects duplicate JSON keys,
nonfinite values, boolean substitutes for numeric metadata, unknown or missing
fields, invalid states, missing files, symlinks, nonregular note files and hash
mismatches. Ledger/note reads are bounded to 256/64 KiB respectively.

Neither mode proves external agent dispatch, actual concurrency, semantic
quality, engineering acceptance or publication. The recorded concurrency ceiling
is schema metadata, not reconstructed execution history. Validation is a snapshot
of the read files; concurrent edits require a fresh run. No ledger row, note,
hash, acceptance status or report is created or repaired by the checker.
