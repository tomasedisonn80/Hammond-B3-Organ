## Architecture boundaries to preserve in the dry engine

These are seams for later work, not a request to implement Leslie processing during M0-M2.

1. **Keep normalized dry amplitude distinct from volts and pascals.** A later calibrated adapter owns conversion into AO-28/122 differential or 147 single-ended electrical ports. Store its source impedance and whether voltage is already loaded so attenuation is not applied twice (pp. 255, 261, 265). Identical dry WAV channels remain an offline transport choice, not a two-microphone simulation.
2. **Keep variant identity composable.** Organ, adapter, amplifier, crossover/driver, motor, cabinet, microphone and room identities must not collapse into one `leslie_type` or brightness setting. Profiles retain source revision, hashes, units, evidence class and explicit unknowns (pp. 253, 259-264, 271, 289, 295, 313).
3. **Retain one engine audio clock and explicit events.** Later semantic Slow/Fast commands use the same sample timeline, independent of key activity. Preserve the current contract's supplied same-offset order; any future host configuration-before-command rule belongs in a documented canonicalizing adapter, not an undocumented core reorder (pp. 256, 292, 319-322).
4. **Do not couple tone-source phase to rotor phase.** Each of the 91 shared tone sources remains free-running; future horn and drum state also persist independently. Note release, silence, repeated commands, transport and UI refresh must not reset any of those clocks (pp. 280, 286, 292, 319, 322). Future delayed acoustics needs read-only historical rotor queries, not another LFO per microphone.
5. **Reserve explicit signal ownership and multiple ports.** The future power stage and reactive load require reciprocal electrical coupling. Horn and bass are parallel acoustic branches; microphone signals coherently sum signed pressure. Optional RV is another fixed radiator. The dry mix must not absorb these systems into hidden gain/filter coefficients (pp. 266, 272-274, 278, 286, 313-316, 334).
6. **Separate preparation from bounded processing.** Profile validation, fitting, geometry, coefficient construction, allocation and destruction remain outside processing. Later solvers, histories, FFT banks and transitions need fixed admitted capacities and diagnostics. M0-M2 stopped-engine replacement is appropriate; the later warm-bank/profile transition plans are not already implemented promises (pp. 262, 268, 274, 304, 327-328).
7. **Keep physical transit distinct from software latency.** Future assets need `response_includes`, reference plane, original time zero, delay-removal record, gain/polarity and sample-rate metadata. A dry engine's zero acoustic delay does not authorize later per-channel peak alignment or extra automatic IR normalization (pp. 280, 298, 305, 317, 325, 333).
8. **Maintain separate acceptance ledgers.** Source topology, mathematical reference agreement, real-time behavior and held-out physical fidelity need separate results. A deterministic dry render may close its engineering gate without claiming any amplifier, cabinet or microphone match (pp. 258, 264, 270, 306, 312, 318, 324, 330, 336).
