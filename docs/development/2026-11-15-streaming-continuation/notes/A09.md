## Header, arithmetic and test conventions

Use a self-contained `#pragma once` header, explicit standard-library includes,
`namespace hammond::research`, `inline constexpr` model/representation identity,
typed counts and declared units. Include it before `TestSupport.h` in at least
one test so accidental transitive dependencies are visible. Match established
`[[nodiscard]]`/`noexcept` conventions and state the preparation, ownership,
capacity, empty-call and transactional-rejection semantics. Core headers must
not include CLI/OS/SDL/VST3 headers. A separate research error vocabulary avoids
unrelated changes to established Engine statuses.

`hammond_configure_target` requires C++20 with extensions off and treats GCC/
Clang `-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Wshadow` warnings
as errors. MSVC uses `/W4 /WX /permissive- /Zc:__cplusplus`. These constraints have
specific implications for a rational/grid trajectory implementation:

- `__int128` is not portable to the required MSVC toolchain and triggers the
  pedantic extension boundary. Use proved fixed-width bounds or explicitly
  implemented bounded limbs, not an implicit compiler extension.
- Check addition, subtraction, multiplication, cross-products, denominator
  construction and shifts **before** performing them. Signed overflow is
  undefined; unsigned wrap is defined but normally wrong for timelines and
  is not caught by ordinary undefined-behavior instrumentation. Guard zero
  denominators and shift counts, including shifts equal to the operand width.
  Avoid `abs(INT_MIN)`/negation of a signed minimum and unsigned subtraction
  before an ordering check. Widen operands before multiplication, not its
  already-overflowed result. `std::gcd` also requires representable magnitudes.
- `long double` is not guaranteed wider than binary64 on required platforms.
  Neither it nor binary64 is an exact ordering oracle for arbitrary uint64
  coordinates or rational roots. Floating-point to integer conversion must
  reject nonfinite/out-of-range inputs before casting; converting UINT64_MAX
  to binary64 can round upward and defeats a naive upper-bound comparison.
- The previous exact binary64/Fraction contract admits subnormals and distinct
  roots sharing a rounded display value. A 64-bit rational pair cannot simply
  stand in for its full domain. If the new grid intentionally quantizes or
  narrows inputs, freeze a new model/admission identity and explicit conversion
  rule. Do not report exact parity with the earlier reference by construction.
- Keep retained command-coordinate/collision identity across calls, endpoint
  tie order, repeated-target no-ops, reversal anchors and partial progress.
  Buffer boundaries must not create new trajectory roundings. Capacity failure
  must leave cursor, all key/contact state, retained admission history and caller
  output unchanged, then allow correct continuation.
- Use integer fields or exact numerator/denominator strings for the probe's
  authoritative event identity. Display doubles are diagnostics. Declare
  deterministic tie ordering independently of an unstable sort. Compare public
  fields explicitly; whole-object `memcmp` can observe padding and does not
  prove semantic rollback. Use `std::bit_cast` for individual binary64 bit
  identities where the frozen contract calls for them.
- C++ tests must use `CHECK`/`CHECK_NEAR` from `TestSupport.h`, not `assert`,
  because required Release builds define `NDEBUG`. Exact grid coordinates,
  bits, counters and partition results need exact checks; approximate checks
  must not hide ordering errors. Independent Python `int`/`Fraction` histories
  should derive expected trajectories without calling native helpers.
- Admission tests should include exact boundaries and one-past limits, empty
  identity calls, same-time command ordering, maximum bursts, many partitions,
  reset/closure/rejection recovery and future-command causality. Check allocation
  on successful and failing prepared operations, but do not promote that result
  to a callback deadline or indefinitely streaming guarantee.
- CLI parsing and output are offline operations. `CliArguments.h` and
  `hammond/detail/Decimal.h` provide established Windows/decimal handling, but
  the decimal helper constructs streams and may allocate; never put it in
  processing. Bound tokens and result bytes; parse integer tokens completely;
  use the classic locale and `max_digits10` for binary64 output. Python should
  reject duplicate JSON keys, nonfinite constants and booleans masquerading as
  integers, and use explicit subprocess timeouts. Preserve inherited sanitizer
  settings when invoking the native probe.
