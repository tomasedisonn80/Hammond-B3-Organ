## Delivered specification and decisions

The contract identifies `causal-contact-grid-v1` as a separate synthetic model.
Its explicit C++20 surface belongs in `hammond::research`, header
`CausalContactGrid.h`. It specifies all configuration, command, rational-time,
edge, result, lifecycle and snapshot fields plus prepare/process/close/reset/
snapshot signatures. Independent implementation and tests can use those names
without choosing their own admission or failure conventions.

The admitted domain is 65536 ticks per host frame, `2^48` position units, one
through four keys with nine independent hysteretic contacts, positive uint32
press/release speeds, three supported rates, 4096 frames and 512 supplied
commands per epoch. All keys initially rest at zero with open contacts. No float
conversion, arbitrary initial state, source waveform, filter or Engine connection
is included. The smaller domain does not inherit binary64-reference equivalence.

Integer commands and integer velocities preserve exact integer command-time
positions, while travel between commands remains continuous. A movement keeps
its original command anchor across processing boundaries and arrivals. Repeated
current targets preserve that anchor. Tied target changes remain ordered and
counted; collapsing them could change the final anchor even without travel.

Crossings retain a whole tick plus a reduced proper uint32 fraction. Root
eligibility precedes narrowing: full travel at speed one has a future quotient
larger than uint32 even though admitted emitted times fit. Comparing proper
fractions needs only uint64 products. The specification includes incoming
threshold equality before commands, stable key/contact ties, right-continuous
bits, and `(cursor,end]` ownership of newly emitted edges. Commands remain in
`[cursor,end)`, so endpoint edges cannot be duplicated by the next call.

Whole-call staging covers state and output, including a late invalid command,
arithmetic guard and short output. Short output reports the actual required edge
count without consuming input or writing output. A conservative capacity bound
cannot reject a call whose actual edges fit. Failure precedence is explicit.
Close applies endpoint targets without travel or edges; N=0 is an endpoint-only
observation. Reset is closed-only; prepare rejects active state. Snapshots expose
complete semantic state and canonical inactive slots, without clock advancement.

## Improved bounds and observed document checks

For M supplied commands in one call and A already-moving keys, the edge ceiling
is `9*(A+M)`. Since each incoming movement needs an earlier accepted command,
`A <= previous commandCount`; therefore call and epoch edge storage need at most
**4608** entries, not `9*(512+4)=4644`. Closure and no-op commands still consume
the epoch command budget but cannot increase this bound.

per interval, normalizes reached roots, and insertion-sorts at most 36 edges per
interval. The resulting per-call maxima are 2052 position evaluations, 18468
