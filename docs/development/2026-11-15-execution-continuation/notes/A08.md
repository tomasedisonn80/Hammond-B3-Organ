## Principal implementation risks

1. Cabinet currently paints after toolbar/pedals; nesting without reordering
   erases their background/caption/keys. Active cabinet parent/art/status must
   precede children; inactive ordering stays literal.
2. The refined drawbar material strip currently begins at label.y+21. Moving
   footage below rails makes that envelope invalid and can suppress the control.
   New active bounds derive from canonical track/cap travel.
3. Existing buttons, presets, key bevels and text use fixed window-space insets.
   Active geometry/material metrics use sx/sy, type requests use min(sx,sy), and
   complete hit/top/front vertices are transformed after canonical front clamping.
4. Existing validation covers bounds/labels but not all applicable values/tracks,
   key quads or clearance. Empty inapplicable fields must remain valid. Preset
   natural endpoints require exact shared construction; 20 intentional overlap
   pairs are valid. Perspective key AABB overlap is not a target collision.
5. Existing active=Flat equality, fixed 22/30 key-inset oracle, separate-cabinet
   gap, y150 percussion and fixed-sized header tests need explicit active-only
   expectation migration. Inactive assertions and ownership semantics remain.
