## Correction and diagnostic contract

UI input replay now retains an independent overlay/focus transition history
before applying the existing musical-snapshot guard. It reserves 512 compact
entries during initialization, deduplicates unchanged overlay/focus pairs, and
fails the replay explicitly on overflow with a truncation flag. Only replay
mode allocates or records this history; no callback, input delivery, action,
audio timing, Session publication, control/state format, or physical claim is
changed. Pointer-down records the opening too, so a header click followed by a
Tab in the same drain cannot lose focus zero.

The schema-version-3 `replay` object gains three additive members:

| Member | Meaning |
| --- | --- |
| `ui_observation_capacity` | Fixed integer 512 |
| `ui_observations_truncated` | Boolean; overflow is an explicit replay failure |
| `ui_observations` | Ordered objects with integer `elapsed_ms`, string `overlay`, integer `modal_focus` |

These describe main-thread UI transitions, not painted frames or acknowledged
audio states. Existing `observations`, their sequence/restoration guard and
capacity, and MIDI-only diagnostics retain their previous meanings and fields.

The original all-eleven-focus assertion remains exact against the appropriate
UI history. A new test runs timestamp-zero keyboard and pointer openings,
requires the ordered MIDI focus sequence 0 through 10 and a final closed modal,
and checks every musical observation still acknowledges the startup restore
and contains the literal audition drawbars, pedal drawbars, and no held notes.
Every modal case checks strict new-entry keys/types, capacity, nontruncation,
and monotonic elapsed times. No sleeps or weakened assertions were added.
