# Staffing sequence and implementation order

This is a work plan, not a participation record. Only successfully dispatched
workers and reviewed returned notes enter [assignments.json](assignments.json).
Each wave has six distinct workers, in two groups of at most three.

| Wave | Purpose |
| --- | --- |
| 1 | Fresh complete atlas reading and source/evidence recovery. |
| 2 | Freeze T2/T3 proposals, independent T2 admission, CI and compatibility review, recovery validator. |
| 3 | Implement T2; independent raster checker; diagnose baseline replay failure; admit T3; prepare next measured header surface and required test transitions. |
| 4 | T2 numerical/visual admission; independent replay repair review; T3 implementation; header protocol admission; targeted comparison fixtures. |
| 5 | T3 numerical/visual admission; independently admitted header material if ready; preservation, installed operation and compatibility checks. |
| 6 | Material/whole-frame reviews, resources/performance, actual UI journeys and operator documentation. |
| 7 | Reconcile complete plan, status, next actions, README, permanent recovery and code review. |
| 8 | Independent installed workflows, source/visual/resource audit and publication readiness. |
| 9 | Exact-source platform results, concrete remaining repairs and release-scope verification. |
| 10 | Final operation, visual/source/recovery/CI reviews and sixty-worker closure. |

Root adapts later exclusive assignments to observed results. A failing candidate
retains its evidence and receives an explicit reviewed correction; no phase,
worker total or missing device/physical/platform gate is manufactured. A proposed
header surface must receive independent admission before implementation. Other
sessions' pending manual/rim/cap/browser/scanner/contact work remains preserved.

## Refined dependency-ready sequence after wave 3

After full T2 paired/visual acceptance, preserve genuine post-T2 binaries and
then implement the admitted five-pass T3 title. Prepare its independent paired
checker and a persistent native title-density regression. A separate header
material proposal must identify uncontaminated reference patches, field/support,
rounding and bounded work; implementation follows independent admission only.
The same genuine-before, after, clip/state, full-frame and resource checks apply.

Later workers own installed user journeys, full compatibility/source audit,
current screenshot/README refresh, complete M0–M9/status/next-step reconciliation,
permanent recovery guidance, exact published CI and final evidence review. Root
publishes qualified chunks with a guarded main update and independently verifies
tree/parent before observing CI. Historical failed/cancelled jobs and unsupported
physical/whole-interface claims remain explicitly separate.
