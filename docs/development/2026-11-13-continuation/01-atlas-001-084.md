## Concrete gaps against the current implementation

### 1. Contact state is the next useful engineering work

The baseline `Engine` has `held_keys_[2][61]` and a Boolean branch gate in
`rebuild_coefficients()`. It has no independently observable contact state,
partial position or release trajectory. That is an accurately named ideal-key
baseline, but does not implement pp. 37-42.

Build a fixed-size contact layer with 1,098 stable manual/key/contact identities.
Keep source lookup, mechanical state and registration routing separate. The atlas
explicitly permits a staged implementation: deterministic ideal contacts first,
threshold crossings second, measured/fitted bounce and fractional switching later
(p. 40). A named nominal trajectory can advance M3 without fabricated captures.

Required engineering acceptance:

- Expose nine separate states for all 122 playing keys, including a strict subset
  closed during partial motion (p. 42, KEY-01/02).
- Preserve independent close/release thresholds and allow per-key differences;
  one universal order is not a hardware fact (p. 39).
- Label ordinary MIDI actuation as a synthetic trajectory. Velocity may affect
  that declared transient model but must not scale steady drawbar level (p. 39).
- Repress from the current incomplete return state, not an invented fully open
  restart (p. 40). Keep shared source phases unchanged.
- Establish exact timing, equal-offset order, zero-frame policy, invalid-input
  atomicity and same-rate block-partition invariance. Reuse the existing engine
  failure contract instead of creating an unbounded second queue.
- Preserve the current ideal mode as an explicit legacy regression fixture while
  introducing trajectory mode. If switching remains sample-quantized, document
  that fractional crossing/band-limited switching is still pending.

No per-key calibrated travel, gap, contact resistance, bounce distribution or
timing tolerance is supplied. The roughly 9 mm/4 mm/2 mm measurements on p. 38
belong to one serviced 1967 C-3 and cannot become universal B-3 constants.

### 2. Complete controls require more than retained A/B banks

The baseline correctly retains 36 manual settings and separates Cancel from
AllNotesOff. It still lacks the two pedal settings, nine fixed registrations per
manual, physical latch-mask behavior and the tablet controls on pp. 49-54.

Page 50 gives both normal exclusive selection and the physical possibility of
multiple latched registrations. Its proposed exclusive enum is a scoped simplified
mode, not proof that the physical mechanism is exclusive. Keep that boundary
explicit when adding fixed presets or a later latch mask.

Percussion eligibility must follow routing selection and the upper-manual B
position (pp. 50-51), rather than current amplitude or a per-note voice. The
percussion normal/soft control and overall normal/soft tablet are distinct
(p. 51). Inactive-bank edits must not rewrite fixed registrations (p. 54).

### 3. Generator scope is useful but deliberately incomplete

The source bank correctly owns one cached free-running sine per source and the
engine coherently reuses those samples. This conforms to the nominal construction
allowed on pp. 43, 63-64 and 69-70. It does not close mechanical topology,
gear-derived tuning, terminal identity, waveform/filter loading or leakage gates.

Page 62 contains a provisional twelve-ratio reference derived from a pinned
setBfree implementation. It expressly does not establish a factory gear inventory,
and the seven upper 192-tooth outputs need their own rule. Do not silently replace
the named 12-TET profile with those values or call them measured.

The existing numerical phase-stall risk remains relevant: `TonewheelBank` accepts
increments greater than zero but advances a double phase by plain addition.
`RuntimeProfile` admits arbitrary positive finite frequencies below Nyquist;
nonzero division alone does not guarantee that addition changes a phase near one.
This is a static review observation, already identified in the inherited log;
this assignment did not claim a new executed numerical test or patch.

### 4. Keep future evidence and model boundaries machine-readable

As M3 profiles expand, preserve trajectory source, profile/model version, units,
unknown physical values and acquisition replacement tasks in authoring metadata
(pp. 15-16, 39, 42). Derived state snapshots must remain distinct from calibration
identity. Diagnostic exports should identify which contact/console model rendered
the result, so a legacy ideal render and a nominal trajectory render cannot share
an ambiguous evidence description.
