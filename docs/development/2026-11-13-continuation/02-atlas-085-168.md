## Next dependency-ready M3 implementation contract

### 1. Contact state before percussion

Add a fixed-capacity contact module with `2 x 61 x 9` independently queryable
connection states and one gesture state per physical key (pp.115-120). Preserve
an explicit ideal/immediate profile as the legacy regression reference. Any
staggered timing, slopes, thresholds or bounce distribution without captures must
belong to a named nominal profile with proposed evidence, separate make/break
values, bounds, units and version.

The first useful extension can implement deterministic synthetic trajectories
and explicit partial-contact events; it must state whether timing is integer-
sample or fractional. It must not claim the p.120 high-rate convergence gate
merely because it sounds less abrupt. Reject malformed traces and capacity or
timeline overflow before musical/output mutation. Zero-frame flushes apply
events without advancing trajectories; cancelled or disconnected audio continues
contact and generator evolution. A release during a held chord never resets
shared sources. Keep final sustained amplitudes velocity-independent.

Required independent checks: peak versus zero-crossing edges; distinct contacts
sharing one folded source; partial depression; interruption/reversal of make and
break; repeated same-sample gestures; held-note Cancel/reselect; equivalent
timestamps across block partitions and supported rates; no callback allocation.

### 2. One shared percussion state and explicit routing

Prepare a manifest and bounded parameter set before adding an envelope
(pp.133-136). The detector uses the **ninth contact / zero-based index 8** on each
upper key (p.128). Its closed state is independent of the 1-foot drawbar gain;
lower keys and pedals do not enter it. Upper B and percussion enable resolve the
selected route; switching must retain control history rather than restart it.

The named readiness surrogate on p.129 provides an initial engineering model:
`q_next = target + (q - target) * exp(-dt/tau)`, with target zero while the
resolved detector is active and one during recovery. Positive time constants,
nonnegative elapsed time, bounded `q`, and a documented gain map are required.
For `dt=0`, retain exactly the previous state. New chord tones feed the current
shared envelope; never freeze the first tone or allocate per-note envelopes.

The atlas derives slow `1.551 s`, fast approximately `0.375 s`, and a simple
recovery product `0.03432 s` from listed nominal components (p.135). These are
electrical hypotheses; adopt them only under an explicitly provisional model,
never as measured attack/decay lengths. Preserve separate controls for
fast/slow rate and bias, normal/soft percussion gain, upper-only attenuation,
and upper-B 1-foot masking (pp.134-138). The selected sustained drawbar must not
become the percussion-volume control. Keep expression on the intended common
path without attenuating twice.

Acceptance distinguishes route correctness, numerical behavior and unperformed
hardware captures: overlap, one remaining upper key, duplicate physical press,
zero-gap off/on, finite and monotonic recovery, lower independence, held B exit/
reentry, tablet changes, Cancel, control restore and block partition invariance.
Specific held-key switch behavior is a named policy until captures establish it.

### Recommended exact nominal API and sample convention

The following is an original engineering proposal for this continuation, not
additional historical evidence. Suggested module responsibilities:

| API/state | Precise proposed semantics |
| --- | --- |
| Prepared `ContactProfile` | Explicit `ideal` or `nominal_trajectory` mode; bounded positive full-travel make/break durations in seconds for the latter; nine make and nine break thresholds per configured key/profile. Require `0 <= break < make <= 1`. Unknown measured thresholds remain separate fields, not aliases for proposed defaults. |
| Key target | Physical-key press/release commands set target 1/0. An optional explicit partial-position command sets a finite target in [0,1]. The physical held-key/ownership flag remains distinct from contacts still opening on release. |
| Key trajectory | Preserve current normalized position on reversal. A simple nominal full-travel slew advances by `1/(Fs*make_seconds)` toward a higher target or `1/(Fs*break_seconds)` toward a lower target, clamped to that target. Use one common motion per key, not nine unrelated oscillators or noise streams. |
| Contact state | A currently open contact closes at `position >= make_threshold`; a closed one opens at `position <= break_threshold`. Between thresholds retain its previous state. Each branch exposes its own 0/1 connection weight. Bounce, fractional edges and electrical conductance are explicit later extensions. |
| Ideal mode | Apply immediate press/release to all nine contacts before rendering the affected sample. Preserve existing dry fixtures and Boolean repeat policy by default. |
| `percussion_eligible` | `percussion_enabled && upper_route_enabled && upper_selected_bank == B`. This is a proposed routing predicate; future fixed presets cannot accidentally qualify through their nine gain digits. |
| Physical detector | OR of upper keys' ninth-contact states, independent of audible registration. The routed detector `g = percussion_eligible && physical_detector` selects decay/recovery, without resetting `q`. |
| Percussion source | Sum current upper contact contributions for the selected second/third harmonic using manual-map drawbar indices 3/4. Reuse the source frame, without selected-drawbar gain. Keep this signal distinct from the ninth-contact detector; partial-travel cases exercise the difference. |
| Sustained 1-foot mask | Suppress only the upper bank-B sustained drawbar branch at index 8 while percussion is eligible. Do not remove the physical contact, stop its source, mute the lower 1-foot branch, or retain the mask on upper A/fixed routes. |
| Shared readiness | One `q` per organ, prepared to a documented initial value (proposed fully recovered 1); no reset on NoteOn, routing, tablet or drawbar changes. Under the proposed routed-detector policy, leaving B permits recovery while held keys remain physically down; returning B uses the actually accumulated `q`. This transition is nominal pending capture. |

For each positive rendered sample at absolute frame `n`:

1. Apply the already merged, stable-order events at `n` to targets and controls.
   Ideal-mode events immediately change contacts; trajectory-mode events do not
   advance position merely by arriving.
2. Resolve contacts at current `position[n]`, then compute route eligibility,
   detector `g[n]`, upper-only compensation/mask and selected harmonic routing.
3. Read the one shared source frame at its current phase. Render the dry and
   eligible percussion paths using current `q[n]`, then apply the common output
   expression surrogate once. A control-only gain does not multiply percussion
   by the selected sustained drawbar.
4. Advance each active trajectory toward its target and advance `q` once for
   `dt=1/Fs`, using the detector and mode resolved for that sample. Advance every
   source exactly once. The next sample observes the resulting states.

This convention makes first-sample behavior testable: a fully recovered ideal
press can render with `q=1` before its first decay step. A nonzero-threshold
trajectory beginning at position 0 closes later according to its declared slew.
It differs in indexing from an advance-before-output recurrence, so tests and
diagnostic traces must use this convention consistently. A zero-frame call
applies/reconciles controls and ideal contact commands but advances no position,
readiness or source. Same-offset release/press introduces no elapsed recovery.
Disconnected output executes identical state evolution. Invalid preflight leaves
all new states unchanged, matching the existing engine's atomicity contract.
