## Decision on the proposed next scope

**The proposed semantic snapshot, numeric entry and drawbar-cap appearance work
is supported by this atlas range and is a useful, bounded M9 continuation.** It
must retain the present musical contract and receive its own implementation,
interaction and visual acceptance. It does not require taking over the ongoing
contact-audio, manual-key, rim, scanner, crossover or rotary work.

1. **Semantic snapshot:** page 433 expressly puts a semantic control model before
   either skin; page 437 requires accessibility queries to read UI snapshots,
   never synchronously enter the audio callback. The current SDK-free copied
   `UiViewState` and `InspectionDocument` are appropriate inputs. A machine-readable
   snapshot is a foundation; it is not a native accessibility provider or proof
   that a screen-reader user can operate the instrument (p. 438).
2. **Direct numeric entry:** pages 418 and 434 expressly require editable numerical
   values and direct entry, with the same retained parameter addressed by pointer,
   keyboard and accessibility operations. Page 417 requires suppression of
   performance shortcuts in text fields while releases still resolve the original
   press owner. This is a real user-facing next feature, subject to the current
   registry's exact ranges and conversion semantics.
3. **Reference-derived caps:** pages 427-432 permit traceable appearance assets
   and separate styling from measured geometry. Preserve cap dimensions during
   travel (p. 428), historic color distinctions plus textual/shape identification
   (p. 435), and unchanged live semantic bindings. Cropping source art can improve
   the declared surface; it cannot establish calibrated construction or literal
   whole-interface equality.

### Numeric-entry contract details to freeze

Page 434's proposed drawbar increments of 0.1 and 0.01 are **input-resolution
proposals**, not physical detents or authority to alter production parameter
meaning. I inspected the current headers: `ParameterBridge.h` defines 47
parameters and requires exact integers for discrete plain values;
`ControlState.h` retains integer drawbar/mixture positions 0-8 and continuous
nominal linear-gain expression 0-1. The numeric feature must preserve that
existing contract unless a separate reviewed state/model migration is chosen.

Before implementation, declare:

- The displayed unit, allowed grammar, locale policy, range, input-length bound
  and treatment of nonfinite, empty, fractional-discrete or trailing characters.
- The immutable captured control/manual/bank/parameter identity for the edit;
  current focus or a newly visible bank must not silently retarget Apply.
- Which user event commits once, which cancels without changing controls, and
  how invalid text remains available for correction with a persistent explanation.
- Modal entry/exit, focus restoration, suppressed still-held physical keys,
  original key-up delivery, pointer capture loss and window deactivation.
- Reuse of the existing command/acknowledgment path. A pending value is not an
  applied or sounding value; failed submission must retain the existing recovery
  policy rather than create a parallel direct Engine mutation route.

`UiModel.h` already separates desired controls from authoritative applied state,
marks text-entry state and exposes `external_parameter`; those boundaries are
more suitable than inventing another saved sound state or parameter registry.
This was source inspection only, not an execution claim.

### Semantic and artwork acceptance boundaries

For semantic snapshots, preserve visible versus retained identities, desired
versus applied values, availability/freshness, focus versus selection, Cancel
versus Panic, named units and meaningful status. Do not export an unimplemented
model as an actionable control or unavailable measurements as zero. A future
native provider still needs its platform mapping, guarded actions, event policy,
screen-reader execution and modal/keyboard journeys. An on-demand JSON export
must not be described as speech or native accessibility.

For cap appearance, retain exact original-image source identity, selected source
coordinates, extraction/resampling/masking recipe, distributed-byte hash and
rights boundary. Preserve actual control count, footage/color order, cap travel,
hit bounds, focus, held/selected/pending indicators, other surfaces and Flat
behavior. Qualify changed native captures against a genuine unchanged baseline,
including endpoints and supported size branches. Source-pixel equality inside a
crop is not whole-frame 1:1; no tests should erase that standing requirement.
