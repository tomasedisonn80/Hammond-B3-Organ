## Implemented behavior

`--replay-time-scale` accepts integer values 1 through 10, default 1. The
programmatic replay and validator interfaces enforce the same bound and reject
booleans, floating-point values, strings and other coerced inputs. A selected
scale multiplies every event's leading timestamp and the 1800 ms duration by
exactly the same integer. Event payloads, order, counts, held ownership, state
bytes, all six default replay byte hashes and scene selection stay unchanged.
The two focus scenes retain their ordinary replay prefix and a final dwell of
250 ms times the selected scale.

The validator requires an integer diagnostic duration equal to the selected
duration and a final painted frame at or after that duration. Every existing
semantic assertion remains: the pre-edit four-owner observation, edited
four-owner observation before a focus scene's fifth hold, exact final controls,
note ownership, complete delivery/acknowledgement, painted held targets, focus
pixels, inert MIDI, and clean shutdown. Increasing time never substitutes for a
missing state observation.

Provenance records `replay_timing` with `time_scale`, `base_duration_ms` and
`duration_ms`. Each case validation returns the same strictly integer mapping;
the orchestration refuses missing, mismatched or type-coerced timing before
marking that case successful. Existing input identities bind the actual replay
bytes. The timeout is still the independent `--timeout-seconds` value, default
12 seconds and bounded to finite 4–60 seconds. No timeout is increased
implicitly and no failed capture is retried.

For root's selected arguments, `--replay-time-scale 3 --timeout-seconds 30`,
the replay duration is exactly 5400 ms and the process timeout is 30 seconds.
This is an explicit capture protocol choice, not a claim that native capture
will pass or that the earlier failed 1800 ms run passed.
