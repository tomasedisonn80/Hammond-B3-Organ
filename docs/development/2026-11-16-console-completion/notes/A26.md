## Exact proposed change

Add the public signature:

```cpp
[[nodiscard]] UiActions recall_controls(const ControlSnapshot& controls) noexcept;
```

Add this complete member definition beside the existing file Load:

```cpp
UiActions UiModel::recall_controls(const ControlSnapshot& controls) noexcept {
    if (!is_valid_control_snapshot(controls)) return {};
    return publish_controls(view_, saved_controls_, pending_control_sequence_, controls, true);
}
```

This is **ten added lines across two existing files, with no removed or modified
existing line**: four public comment lines, one declaration, four definition
lines and one separating blank line. There is no production include, data member,
constructor change or new command/state/parameter identity. Neither LibraryModel,
Session, Engine, main, browser, painter, CMake nor existing tests are edited.
The separately specified parameter-gesture closure remains a distinct task.

## Required behavior and boundaries

The retained publisher writes only `view_.controls`, `view_.controls_pending`,
`view_.controls_dirty` and `pending_control_sequence_`, then returns one
`SessionCommand` holding a copied `ControlSnapshot`. It performs no I/O, Session
post, callback work or Engine access. The complete snapshot crosses the existing
variant unchanged; this helper does not infer Registration versus Performance,
merge expression, select a bank or normalize a recalled value.

A valid Recall always sets desired controls and pending, including when the values
are identical to desired or applied controls. The publisher resets the old pending
sequence; the caller then reports this action's actual post result through
`submitted`. It is that real successful post, not this helper, that supplies a
new nonzero Session sequence. `view_.applied` stays unchanged during the helper.
The existing observation path settles ordinary UI pending state; the stronger
named-receipt Applied proof remains exclusively in LibraryModel.

Recall does not assign `saved_controls_`, call `load_controls` or call `mark_saved`.
With retained legacy baseline **S**, recalling **R != S** is dirty, including a
same-value repeat of R; recalling **S** is correctly clean while still pending.
This is a comparison to the original baseline, not a promise that Recall always
leaves the dirty flag true. Legacy Load continues to install its loaded snapshot
as the clean-file baseline. Explicit legacy Save still marks its exact completed
copy through the unchanged `mark_saved` path.

The helper leaves layout, edited banks, workspace/presentation, focus and workspace
focus memories, roving keys, keyboard target, manual/pedal octave, text-entry state,
pointer capture, physical/suppressed inputs, parameter gesture, keyboard/pointer/
Space holds, last submission status and recovery flags untouched. A later failed
post still uses the existing rejection policy, which deliberately clears local
owners, adopts last applied controls and computes dirty against S. Preserving that
policy does not mean a transport rejection must preserve held notes. No retry or
new optimistic acknowledgement rule is introduced.

These source properties preserve all existing 47 parameter identities,
`B3CONTROLS4`/readers 1–3, 91 running sources, plugin UUIDs and nominal dry Engine
inputs. They do not themselves execute a musical-history, device, browser,
accessibility, fidelity, timing or literal whole-interface 1:1 gate.

## Concrete independent acceptance cases for A27

The expected results below derive from the public contract. The test author owns
fixtures and assertions independently; none should call the private publisher,
read private state or derive expected controls by running the proposed helper.
Use actual Session post/read/render boundaries when claiming application or
transport behavior. Compare value fields explicitly rather than struct padding.

1. **Complete owned copy.** Construct four distinct nine-value banks, selected
   banks A/B, both routing values, non-None fixed memories including a cancelled
   manual, distinct pedal mixtures, all percussion settings and expression 0.375.
   Require exactly one outer SessionCommand whose inner alternative is the whole
   literal candidate; desired equals it and applied remains the prior snapshot.
   Mutate the caller's candidate after return and verify both returned action and
   desired copy stay unchanged. Also call with `ui.view().controls` as the argument
   to exercise a valid self-aliasing reference without a second action.
2. **Same values still have a new intention.** Recall a currently applied saved S,
   require one action, pending true and dirty false; post it to a real Session and
   retain its nonzero sequence. Before rendering, a fresh unchanged Session read
   must leave it pending. Render and observe, then repeat S and require another
   successful sequence greater than the first, with the same full payload.
3. **An older equal-valued completion cannot settle a new unsubmitted Recall.**
   Post a first R and obtain its real rendered snapshot. Before delivering that
   snapshot to UiModel, generate a second Recall of the same R. Deliver the old
   snapshot before the second post: the second intention remains pending. Post
   the second action, deliver the old snapshot again, then render/observe the
   second sequence. Only the ordinary resolution of the latter clears pending.
4. **The legacy baseline is retained.** Establish S through legacy Load and its
   real acknowledgement. Recall R different from S: dirty stays true before and
   after application; repeat R and remain dirty. Recall S: dirty is false even
   while pending. Recall R again: dirty is true. Legacy Load R must still rebase
   to clean, after which Recall S must be dirty. Include a difference only in
   expression; this helper compares complete controls, not a Registration-scoped
   named-reference comparison. `mark_saved` continues to mark only its passed copy.
5. **Invalid candidate is atomic, including pending bookkeeping.** Independently
   corrupt every field category: a drawbar position 9 in each retained bank,
   selected-bank enum 2 for either manual, invalid fixed-registration enum,
   pedal position 9, each percussion enum 2, and expression NaN, infinity, negative
   or greater than one. Preserve the full public view/layout and emit zero actions.
   Repeat while a prior valid action is actually submitted but pending, then
   render its real sequence: it must still resolve normally, demonstrating that
   invalid Recall did not erase the earlier sequence. A later exact return to S
   must still be clean. Do not fabricate invalid `bool` object representations.
6. **Presentation and interaction state survives.** Arrange nondefault edited
   banks, remembered workspace focus, roving notes, keyboard target, both octave
   settings and text-entry state. Cover Play/Rotary/Service and Dimensional/Flat,
   with minimum and canonical layout sizes. Immediately around Recall, compare
   every public field except desired/pending/dirty plus all layout fields; applied
   and recovery/status fields remain unchanged. A parameter drag is not closed by
   this helper: that separate public operation is outside A26's proposal.
7. **Original owner releases survive successful Recall.** Hold independent
   keyboard, Space, pointer and external notes through a real Session; include
   an external owner overlapping a UI note. Change focus, keyboard target/octave
   and workspace before Recall, record the exact pre-call state, then recall and
   render zero frames. Holds and frame clock remain; the action contains no
   ReleaseUiNotes/Panic/NoteOff. Original Ups must emit their original pitch/bus/
   owner and release only those owners, including pointer Up outside the window.
   Repeated Down cannot retrigger a held key. A previously released note must not
   reappear. The overlapping external owner survives the UI Up until its own Off.
8. **Existing rejected-post semantics remain.** Fill a real Session's bounded
   queue, generate valid Recall R, and observe the actual QueueFull result. After
   `submitted`, expect the existing recovery policy: no automatic retry, pending
   false, desired restored to the prior applied copy A and dirty exactly
   `(A != S)`. Flush the real recovery and retain its counter/held-state outcome.
   Use S distinct from A so accidentally rebasing to R or marking clean is visible.

Existing `pending_saved_and_recovery`, preset same-value activation and
`test_standalone_workspace_continuity.cpp` provide established adjacent regression
coverage, not a passed test of this new API. A real paired Session/audio comparison
may additionally establish the new helper's whole-snapshot route under held-note
phase/percussion continuity; existing A19 results alone do not test its call site.
