## Concrete delivered design

The new SDK-free header gives the implementation owner concrete copied
types and effects for refresh, control intention, Recall and Save. `LibraryModel`
is the sole mutable catalog/draft/selection/current-reference/receipt owner.
Its PIMPL keeps internal acknowledgement proofs and named baselines out of the
browser view. Main-thread allocation is allowed; no audio-thread use is admitted.

The accompanying design specifies:

- Exact stable-key catalog replacement with bounded structural validation,
  stale/duplicate generation rejection, preserved stale rows, atomic name-draft
  validation and Missing determined only by a suitable complete catalog.
- Separate selected entry, current named reference and operation target, with
  Registration expression exclusion only in the exact existing scope helpers.
- Monotonic finite IDs/revisions, including equal-value new intentions and a
  unified mandatory report of **every** actual post result. Direct MIDI or
  recovery failure cannot be hidden merely because it bypasses `UiModel`.
- Fresh coherent snapshot validation, original pre-post publication/counters,
  nonzero exact accepted control sequence, and no proof reconstructed from a
  later unrelated sequence or counters captured only when Save is clicked.
- Explicit Recall returns one copied snapshot intention and never marks Applied
  on queue acceptance. Save returns one create-only storage effect only after
  a genuine acknowledgement basis exists.
- A fresh final-save authorization is the linearization point. A valid past
  copy survives later audio publication for the sole purpose of truthful
  completion; no committed file is undone or described as absent.
- Committed malformed metadata remains **SavedWithWarning** without false
  current-reference promotion. Post-save generation-zero scan results are mapped
  to a generation reserved before the storage effect, and a newer explicit
  Refresh wins.
- Failed reads, supersession, saturation/exhaustion, precise two-second timeout,
  rapid lifecycle notifications, prepare invalidation, late results and duplicate
  effects/authorizations have explicit fail-closed behavior.
