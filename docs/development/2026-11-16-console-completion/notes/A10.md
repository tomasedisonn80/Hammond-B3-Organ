the original pre-post proof and failure guards, supersedes equal-valued older

## Amendments resolved with A07

1. Added explicit malformed/stale observation and catalog admission rules,
   including same-publication conflict detection and Missing only from a complete
   admitted scan.
2. Preserved reported disk commits as SavedWithWarning when metadata or refresh
   cannot justify a clean success; malformed metadata cannot promote a false
   current reference.
3. Reserved the post-save generation before issuing I/O, remapped the real
   storage helper's generation-zero refresh, and protected newer explicit scans.
4. Clarified rollback of failed/unproved optimistic desired values without
   invented proof; added validated explicit `latest_desired` to Recall so
   Registration's expression merge follows the actual UI value at activation.
5. Kept case-collision Ambiguous rows disabled until a complete catalog scan,
   and required consistent counts when a changed entry preview is replaced.

## Next action and limits

Root can assign implementation and meaningful tests against these pinned inputs.
Priorities are a real Session acknowledgement harness; failed/older/conflicting
reads; synchronous MIDI/recovery failures; equal-value supersession; all four ID
exhaustion limits; lifecycle hooks; timeout boundaries; Save staging/fresh final
authorization; committed-with-warning results; and stable catalog identities.
The admission contains the concrete cases, including forged count arithmetic.

Future main integration must report every actual post result, deliver fresh
observations and lifecycle transitions, and use a named-recall helper that leaves
the legacy saved-file baseline intact. Existing `load_controls` is unsuitable
because it changes that baseline. The explicit latest desired input must come
from `UiModel::view().controls` when Recall is activated.

This verdict does not admit implementation, native browser wiring, real-device
journeys, UI equality, builds, tests, commits, pushes or release. Root owns those
subsequent gates and publication. If the pinned API or semantics change, review
the affected boundary again before claiming this admission applies.
