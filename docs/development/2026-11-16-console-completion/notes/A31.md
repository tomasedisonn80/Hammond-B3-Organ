## Finding and candidate

The existing JSON reader rejects `NaN`/`Infinity` through `parse_constant`, but
ordinary numeric exponent overflow uses `float` and can become infinity.
Source inspection identifies a concrete acceptance gap: positive overflow in
`runtime.rendered_images` or the endpoint's resolved/applied sequence can pass
the current progress/acknowledgement comparisons; negative overflow in the last
submitted sequence can lower both acknowledgement thresholds. Those fields are
not copied into the validation result, so the finite-only provenance writer
cannot reject them. This is a source-derived risk, not an executed claim that
the native producer or any original capture emitted invalid evidence.

The minimal production diff adds only a local `parse_float` finiteness hook in
`read_json`, with a useful token-bearing `ValueError`. Default finite float
conversion, integer parsing, nested values, duplicate rejection and the existing
constant error remain intact. All replay/state generation, 15 optional/default
case identities, timing-scale rules, independent timeout, semantic assertions
and no-retry behavior remain untouched.

Six new methods cover signed overflow at nested object/array positions; finite
float boundaries, rounding, exponent notation, subnormals and signed zero;
unchanged other JSON types/top-level object rule; duplicates including escaped
names; existing invalid constants; and the four concrete capture evidence
fields. All 39 existing methods and every existing helper remain text-identical.
