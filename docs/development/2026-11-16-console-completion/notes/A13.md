## Implemented catalog and presentation boundary

The PIMPL retains copied catalog, draft, exact selected key, actual observation,
latest desired intention/basis, one named receipt and an independent current
reference. It calls only the existing pure registration name/scope/control
helpers. It performs no filesystem operation, Session call, SDL action, audio
submission, callback work, clock read or event pumping. Construction, copied
views and bounded main-thread state may allocate.

Catalog replacement accepts the newest outstanding explicit generation once.
Generation zero, unsolicited results, duplicates and late results cannot replace
rows, scan status or selection. A malformed complete catalog or recognized failed
scan retains the prior rows and Missing flag and marks the catalog stale. Failed
scan partial rows and counts are never copied. A later complete admitted catalog
is required for another new Recall/Save request.

Complete admission checks all enum identities, exact valid stem/suffix/key
agreement, strict folded-name/scope/exact-key order, unique exact keys, collision
groups, payload validity and disjoint derived warning counts. In particular,
the real storage helper excludes Ambiguous rows from `invalid_entry_count`;
candidate count is retained rows plus omitted invalid names. Bounds are checked
before additions: at most 128 rows/candidates and 512 directory items. Complete
Empty catalogs may still contain omitted-name warnings, as storage actually
allows. MissingDirectory requires zero rows/counts. Ambiguous rows cannot regain
Recall eligibility from a single-file read.

Names/drafts remain at most 48 bytes under the existing ASCII policy; neither
keys nor names are truncated. Every retained detailed diagnostic is copied from
at most 256 input bytes, rather than first allocating an unbounded source string.
Selection follows exact keys through refresh. The first successful nonempty scan
selects its first row; removal of a previously selected key clears selection
without choosing a replacement. Relative movement clamps without wrapping and
widens `int` before arithmetic, covering the full signed input range. Disabled
rows remain inspectable. Draft/scope edits never retarget a receipt.

## Original control proof and outcomes

Each valid complete intention, including an equal-valued intention, obtains a
new desired revision before its one actual post result. A basis retains its
original pre-post publication, resolved-sequence floor, expected complete
controls, failure guards and accepted nonzero sequence. A failed original read
does not become a valid pre-post observation later. Such an accepted intention
remains visibly pending until resolution, but cannot establish a proved basis.

Every non-Ok post result advances synchronous failure history, including results
without a control token. Recognized failure names appear in bounded diagnostics.
Malformed results, zero/nonincreasing accepted sequences and mismatched tokens
cannot establish proof. Accepted sequences must also exceed the latest admitted
resolved-sequence floor. Non-control accepted posts never create a control basis.

Proof requires a newer original publication, both sequence fields covering the
accepted sequence, unchanged unsaturated recovery/rejection/discard/failure
guards, the same desired revision and complete expected/desired/actual equality.
Already proved copies retain their original proof; a new Save captures fresh
receipt guards and may reuse an unchanged proved copy after an unrelated failure.
An already waiting operation is invalidated by that intervening failure.

Observation validation checks complete controls, coherent lifecycle/revision and
sequence relationships, supported prepared sample rates, finite nonnegative
peak, known fault/status values and monotonic relevant counters. Repeated
publication revisions must match every SessionSnapshot field, including holds,
clock, floating bit identities, lifecycle, counters and statuses. A failed,
older, malformed or conflicting observation preserves actual display and cannot
prove a receipt. Actual controls are adopted after failed/recovered unproved
intentions without creating a revision or acknowledgment.

### Late-token interpretation sent to root and A16

Design section 4 requires both that stale/duplicate/mismatched control tokens
fail named proof closed with ProtocolError and that an older completion not
overwrite a newer valid pending intention. The implementation combines those
rules explicitly: an old **accepted** token with a nonzero revision below the
latest while a newer intention is pending returns ProtocolError, attaches no
sequence and finishes an active named wait, but preserves the newer pending
basis and desired controls. This also applies when its accepted sequence is
already stale. Malformed/current-token protocol failures invalidate affected
proof. An actual **failed** post always changes global failure history and
invalidates affected waits regardless of token age. A16 has this exact behavior
for independent review; this note does not claim those tests have passed.

Recall uses only the explicitly supplied validated latest desired controls as
its expression merge source. A changed parsed selected entry updates its preview
and requires a second activation; invalid matching entries become disabled.
Registration and Performance use the existing pure scoped merge. Only an
acknowledged matching receipt establishes Applied/current origin Recall.
Selection, same-valued newer intentions and old receipts cannot substitute for
that proof. Modified compares actual acknowledged controls with the independent
reference baseline using its exact scope; Pending is a separate intention state.

## Save, lifecycle, time and finite limits

Save refuses an absent, invalid or unsubmitted basis, a stopped unproved staged
copy, stale catalog, invalid final name/scope, known case collision or exhausted
catalog capacity. It may wait on a valid original submitted basis or use a proved
unchanged prepared copy, including while stopped. Its captured target and complete
snapshot remain separate from later form and selection changes.

Taking ReadyToSave performs a fresh proof check, reserves one post-save catalog
generation and issues one copied storage effect. No reservation means no storage
effect. The mandatory final authorizer performs another fresh observation,
deadline, identity, basis and failure-guard check. A failed final read cannot use
the cached display. One true authorization consumes permission; subsequent
controls, lifecycle notifications, exhaustion or elapsed time cannot cancel that
authorized Saving receipt before its actual storage result arrives.

Known storage failure is SaveFailed. NotAuthorized after a prior refusal retains
that refusal's specific terminal outcome. Unknown/duplicate operation results
cannot overwrite a receipt. A reported committed outcome with missing/mismatched
metadata or missing model authorization is SavedWithWarning and cannot establish
a false named reference. A valid committed result establishes AcknowledgedSave
from the staged copy, never submits audio and never moves the legacy clean
baseline.

The storage helper's generation-zero post-save catalog is validated and remapped
to the reserved generation. A newer explicit refresh wins. Missing/malformed/
failed refresh or changed committed-row data produces a committed warning and
cannot become SaveFailed or trigger retry. A newly saved reference starts Missing
false; already requested pre-save catalogs cannot newly assert its absence. The
known post-save compound scan or a subsequently requested complete scan can.
Reservation itself does not mark a previously complete catalog stale if storage
then fails before commit; a failed postcommit refresh does.

All four injected ID limits start from zero and issue 1 through the configured
limit without wrapping. An attempted increment beyond any limit permanently
closes named mutation tracking with Exhausted; reaching the last issuable value
alone does not invalidate it. Saturated Session failure counters cannot authorize
a new receipt. Time is supplied monotonic milliseconds: a regressing value supplies
no proof, a request whose 2000 ms deadline would overflow rejects, and an
unresolved receipt times out at `now >= deadline` before testing acknowledgment.
Timeout remains Unconfirmed even after a later successful observation. Stop/Start
hooks invalidate unproved bases and cancel waits; Prepare invalidates even proved
bases. Observed lifecycle transitions provide the same backstop. Authorized
storage completion remains protected throughout these transitions.
