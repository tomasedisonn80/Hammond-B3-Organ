## Behavior and acceptance boundary

The Python standard-library checker derives its session and repository from its
own file. It reads only `assignments.json` and the applicable note files. There
is no `--repo` option, no ledger rewriting or sorting, no acceptance mutation,
and no generation of actual assignment records. Optional `owned_paths` remain
unchanged; they receive relative-path syntax checks without claims of ownership
or existence. The actual A15-before-A14 record order is preserved.

Default progress allows incomplete dispatch and missing or partial **unpinned
running** notes. Only `state: accepted` counts as accepted. Any other state than
`running` or `accepted` is refused. An accepted record requires a nonblank
`root_review`, its exact `notes/Axx.md` ordinary UTF-8 file, and a matching
lowercase SHA-256. The documented mechanical note floor is 300 bytes, 200
non-whitespace characters and 30 whitespace-separated tokens. This rejects
empty/padded placeholders without pretending to judge substantive quality.
An optional hash on a running record is checked and never accepts it.

Both modes enforce this session/base identity, integer requested counts
**60 / 10 / maximum 3**, canonical A01–A60 IDs, the matching wave and
`/root/wXX_aYY` agent identity, uniqueness and at most three currently running
records. Strict adds all sixty accepted records and ten complete six-record
waves. Duplicate JSON keys, malformed records, undefined acceptance semantics,
missing/changed final bytes, mismatched hashes, bad paths and symlinked ledger
or note paths are refused. Plans, historical entries, queues and followups
never contribute worker credit.
