`apps/standalone`. With `BUILD_TESTING=ON`, the existing

native option off, these five library suites remain part of the ordinary build
and unfiltered core CI. The pending recall helper must exist before its dependent

The P1 numerical CTest is added inside the existing native-on/testing-on block,
immediately after the already registered native fixture:

```cmake
add_test(NAME test_standalone_performance_plate_numerical
    COMMAND "${Python3_EXECUTABLE}" -B
        "${PROJECT_SOURCE_DIR}/tools/compare_performance_plate.py"
        --candidate-only --after "$<TARGET_FILE:test_standalone_performance_plate>")
```

It uses the configured interpreter, source-root script path and target-file
generator expression. This works with configuration-specific executable locations
and Windows suffixes; it assumes no external SDL checkout path, historical binary
path, working directory or `python` executable name. The real fixture uses
`SDL_Init(0)` with a software surface, without opening audio or a window. The
existing native aggregate already builds it exactly once. A Python CTest is not
added to the C++ target list.

Labels are `standalone;native;material;performance-plate;numerical`. The finite
CTest limit is 180 seconds in ordinary builds and 480 seconds with sanitizers,
an **8/3 multiplier**, matching the existing P1 fixture's material-gate budgets.
This is an execution budget, not a rendering-speed criterion. The comparator's
existing 60-second per-process guard, no-retry behavior, byte ceilings, source

fixture's inventory and canonical case 0; it does not invoke the eight-process
