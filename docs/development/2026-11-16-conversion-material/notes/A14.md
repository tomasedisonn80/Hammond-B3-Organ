# A14 — strict contact-grid certificate command

## Scope and current position

Read the standing agent instructions, project plan, complete admitted
[conversion contract](../../../CONTACT_GRID_CONVERSION_CONTRACT.md), its
[independent admission](../../../reviews/CONTACT_GRID_CONVERSION_ADMISSION.md),
and the original filesystem/parser implementation. Implemented only
`tools/convert_contact_grid.py` and `tests/test_contact_grid_conversion_cli.py`.
The numerical owner is A13; its agreed API and absolute `time.monotonic()`
deadline are unchanged. No original kernel, IO module, fixture, CMake, Engine,
parameter/state identity, UI, build tree or installation was modified by A14.

The command requires one `--input` and one `--output`, admits no abbreviations,
stdin/stdout sentinel, extra flags or implicit help-success path, and invokes
the original strict input/path admission. It hashes the actual four Python
modules and contract, supplies one shared 30-second deadline to both numerical
conversion and certificate reconstruction, and checks those files again before
publication. The entire bounded certificate exists before any temporary output.

Publication rechecks the original path plan, creates a same-parent temporary,
writes all bytes, flushes and fsyncs, rechecks the path plan again, checks the
deadline and performs one `os.replace`. The original regular destination can be
replaced only on success. Failures clean only the command's owned temporary.
Successful replacement is the irrevocable commit point: later signal handling
cannot report an unpublished refusal. SIGINT is deferred only through temporary
ownership acquisition and the short replacement/bookkeeping window. A signal
pending before replacement aborts with 130; a signal delivered during replacement
is resolved according to its actual success/failure. Handler state is restored.

Success returns 0 with empty stdout/stderr. Refusals return 2 with one strict
ASCII-safe JSON line of at most 8,192 bytes; precommit interruption returns 130
with the same bounded protocol. Invalid-input messages are sanitized and capped.
An exact witness too large for the diagnostic cap becomes an explicit resource
refusal rather than a truncated mathematical claim. The unchanged path semantics
allow resolved input/parent symlinks and reject output-leaf symlinks, hardlink
aliases, missing parents and nonregular endpoints.
