## Delivery and ownership

Implemented [check_session.py](../reports/check_session.py), a Python standard
library validator matched to this session's actual `assignments.json`, plus the
compact [verification receipt](../reports/A09-validator-verification.json).
This note, the checker and the receipt are the only paths written by this worker.
The ledger, checkpoint, production code, other session notes, coordinated build
and publication remain with their assigned owners. No worker was spawned and
no commit or push was performed by this worker.

The checker defaults to progress admission. It permits zero through sixty
recorded actual workers and permits a running worker without a finished note.
It reads only this session's ledger for counts. Strict closure is an explicit
additional mode requiring all sixty accepted records and six verified records
in each of ten waves. `valid: true` in progress mode does not claim closure;
`strict_record_closure` is false until a successful strict run.

## Admission rules

- Pin the exact current ledger schema, base commit, sixty-worker target, ten
  waves and declared three-worker concurrency limit. Reject unknown fields,
  wrong types, booleans used as integer metadata, duplicate JSON fields,
  malformed encoding, nonfinite JSON constants and oversized records.
- Require exact unique IDs `A01` through `A60`, their arithmetic wave mapping,
  and exact unique canonical names `/root/w01_a01` through `/root/w10_a60`.
  Planned entries, follow-up aliases and noncanonical names are rejected.
- Require a task description of at least three words and, for accepted rows,
  acceptance prose of at least six words. Obvious placeholder-only prose is
  rejected. Running rows cannot carry the accepted note/hash/acceptance fields.
- Require a nonempty list of exact repository-relative owned paths, including
  the worker's canonical current-session note. Reject path traversal, absolute
  paths, empty components, dot aliases, backslashes, glob/control syntax,
  common Windows aliases, symlinks and different existing paths naming one
  inode. Owned scopes may name files that have not yet been created.
- Require each accepted note at
  `docs/development/2026-11-16-runtime-continuation/notes/Axx.md`, a lowercase
  64-character SHA-256 matching its actual bytes, readable regular UTF-8 content,
  and at least forty prose words including twenty distinct words. Headings,
  comments and code blocks alone cannot satisfy that modest narrative floor.
- Reject duplicate accepted note bytes and hard-link note aliases. Compare
  accepted note hashes against other retained `docs/development/*/notes/*.md`
  files to reject exact copied-note reuse. Historical notes supply only this
  negative reuse check; none supply current worker counts or acceptance.

The checker reports counts, missing and unaccepted IDs, each wave's counts,
current ledger/source hashes, comparison count and structured error locations.
It emits JSON to standard output and exits zero only for an admitted record set.
Normal checks make no filesystem writes. The self-test writes exclusively to a
temporary directory and removes those synthetic fixtures on exit. Use `-B` as
shown below when importing/running Python during verification to avoid bytecode
cache artifacts.

## Limits and next owner

This checker establishes retained-record consistency only. It cannot prove
actual/new external dispatch, chronological execution, measured concurrency,
exclusive ownership or sequential handoffs, substantive acceptance, numerical
correctness, test execution, product quality, publication or physical fidelity.
Canonical agent strings are session-local assertions and can recur in different
root sessions; they are not global proof that workers are new. Exact old-note
hash comparison does not detect a copied note that has been edited. Prose word
counts detect empty or obvious placeholder records, not the truth or value of
their contents. Owned paths are declared scopes rather than a verified list of
completed artifacts. Ordinary reads do not lock the live ledger or notes.
