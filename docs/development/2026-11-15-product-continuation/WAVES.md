# Ten logical development waves

The owner requested sixty actual distinct agents. The machine admits three workers at once; work is dispatched in dependency-ready tranches. This plan is not an execution ledger: only `assignments.json` records agents actually spawned, their owned files, outcome and note hash. Each completed wave must contain exactly six distinct worker identities. Follow-up messages to one worker do not create another agent.

| Wave | Actual ID range | Purpose and exit evidence |
|---|---|---|
| 1 | A01–A06 | Entire500-page atlas coverage, source identities and project-wide findings |
| 2 | A07–A12 | MIDI, calibration, visual and circuit contracts; independent contract reviews |
| 3 | A13–A18 | Native implementations, independent analog reference, CLI/lifecycle and modal UI |
| 4 | A19–A24 | Independent response/conservation, MIDI queue, diagnostic-schema, raster and interaction acceptance |
| 5 | A25–A30 | Allocation, complete synthetic controller flow, paint timing, same-Hz characterization and compatibility/portability review |
| 6 | A31–A36 | Packaging integration, usable guides, visual comparison, README design and complete-plan reconciliation |
| 7 | A37–A42 | Instrumented and full integration checks, capture-tool admission, actual native gallery and independent image/overlay review |
| 8 | A43–A48 | Installed workflows, provenance, bounded storage/recovery, strict actual-agent accounting, fault lifecycle and numerical boundary review |
| 9 | A49–A54 | Source-identified hosted platform results, VST3 compatibility, documentation claims and visual acceptance |
| 10 | A55–A60 | Independent final product review, concrete next-phase gates, accounting and publication/recovery closure |

Assignments may be refined when a real failure identifies a more useful task. Do not add tests that simply restate implementation, repeat already sufficient verification, count historical agents, or present plans as results. Preserve numerical, physical-device and visual-reference limitations separately. Root integrates shared files and publishes accepted work without force, with expected-head and exact-tree verification.
