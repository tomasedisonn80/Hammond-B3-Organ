## Actual source comparison

The relevant public code already implements much of the timing and routing
foundation described in these pages:

- `TonewheelBank` is explicitly `ideal-shared-sine-v1`. Its value-owned state
  evaluates `peak_amplitude * sin(2*pi*phase)` once for each of 91 sources.
  Preparation seeds a new field; stopped rate reconfiguration preserves phase
  and updates only admitted increments. There is no general harmonic waveform
  or mechanical-residual representation in `ToneSource`/`RuntimeProfile`.
- `tools/compile_profile.py::validate_profile` deliberately requires the exact
  named nominal profile and says arbitrary tuning/amplitude/phase/routing needs
  a distinct model version. Adding Fourier coefficients to this existing format
  would silently violate its contract.
- `ContactBank` already has 1,098 contact bits, independent per-key nominal
  thresholds, separate press/release durations, partial-position targets and
  stopped rate migration. It has only Ideal and LinearTravel modes. These are
  sample-boundary closure states, not a fractional-edge antialias renderer or
  measured contact/bounce model.
- `PercussionState` is explicitly `shared-readiness-v1`, with one continuous
  dimensionless readiness state, calculated RC hypotheses and named proposed
  gains. Its header correctly disclaims a voltage model or complete AO-28.
- `FixedRegistration`/`ControlState` already expose the exclusive 12-choice
  selector, retained A/B banks, separate Cancel route state and copied controls.
  They explicitly do not implement physical simultaneous latch loading.
- `PedalBusKernel` preserves independent mapped branches. `PedalVoice` uses a
  documented fixed 2-by-4 mixture and linear control gain. It correctly labels
  those as dimensionless fixtures rather than reactor response or calibrated
  16-foot/8-foot voices. Sources 1-12 remain sine waves in the shared bank.
- `Engine::process` mixes the shared nominal field, percussion and pedal output,
  then multiplies by fixed output gain and the normalized expression surrogate.
  The general loaded drawbar/expression/pedal networks are absent; research
  changes should preserve the compatibility identity and dry default arithmetic.
- `tests/test_tonewheel.cpp` contains elapsed-time phase and same-waveform
  sample oracles, seed fixtures, silent advancement and failed-prepare checks.
  `tests/test_pedal_sources.cpp` tests shared source identity, contact branches,
  rate transitions and block partitions. These source inspections describe
  existing test intent; I did not execute these tests or claim new passes.

## Recommended independent next development

**Preferred M2/M3 candidate: a separately identified harmonic-source research
bank and scalar oracle**, grounded in pages 93, 103-108 and 139-144. This is
useful without inventing instrument measurements and avoids the current owners
of ScannerLineFoh, named registration storage/browser, M6 FOH, visual deck,
native MIDI retirement and R4.

1. Freeze a new bounded coefficient contract: source ID, coefficient phase
   convention, electrical-cycle domain, source boundary, engineering versus
   measured units, explicit sample-rate/harmonic limits and original provenance.
   Keep the current profile/compiler and default Engine unchanged.
2. Implement an independently testable fixed-capacity source evaluator with
   one continuous source phase per ID, distinct intrinsic harmonics and borrowed
   source identities, transactional preparation and stopped rate migration.
3. Require a separately computed scalar harmonic oracle, exact single-sine
   reduction, mute/phase continuity, complex phase checks, shared-source pedal/
   manual coherence, bounds/rollback, rate/partition checks and callback
   allocation instrumentation. Do not optimize into tables until measured error
   against that oracle justifies it.
4. Supply an offline research render/probe with clearly synthetic coefficient
   fixtures and machine-readable identities. No guessed historical odd-partial
   strengths, global detune or generic hum should be installed as measured B-3
   defaults. Later live integration needs an explicit compatibility/recall plan.

**Alternative M3 candidate: bounded fractional-contact reference and convergence
experiment**, directly required by pages 115-120 and the retained
`M3_REMAINING_AND_SCANNER_GATE.md`. It would establish an executable gate before
an optimized contact renderer is selected. Peak and zero-crossing edges, repeated
folded sources, simultaneous/fractional edges, partial depression and tails
across block boundaries are essential. The `1e-4` target needs a frozen gain,
latency and reference-convergence convention; a mere oversampled base-rate
output cannot satisfy it.

Loaded drawbar, expression, pedal reactor and percussion circuit improvements
remain legitimate later work, but the atlas does not supply all production
connectivity, impedances, capacitance curves or specimen data. An independent
declared network can be studied now; its numerical pass must not be relabeled a
measured instrument or a completed M3/M5 gate. Simultaneous latches should not
be made audible by summing registrations before the missing network is defined.
