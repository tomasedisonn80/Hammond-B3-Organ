## Current public interfaces inspected

The review inspected `include/hammond/TonewheelBank.h`,
`src/TonewheelBank.cpp`, `include/hammond/Profile.h`,
`include/hammond/Engine.h`, and relevant phase/profile handling in
`src/Engine.cpp` and `HostTimeline`.

1. `TonewheelBank` is explicitly `ideal-shared-sine-v1`. `process_frame`
   computes one normalized sine per source at current phase and then advances
   that phase. There is no harmonic source, pickup, generator-filter or leakage
   coefficient representation in this class.
2. `RuntimeProfile::sources` stores frequency, peak amplitude and base phase
   only. It is a value-owned, bounded preparation input with an explicit
   unmeasured nominal profile ID. Its loaders run with audio stopped.
3. The source bank already has transactional preparation and sample-rate
   reconfiguration. Reconfiguration preserves phase and updates validated
   increments. Its `[2^-53, 0.5)` increment support bound is a numerical contract
   that later evaluators must not silently weaken.
4. `Engine` is explicitly nominal dry and owns contact, pedal and shared
   percussion histories. It exposes copied control/phase/contact diagnostics
   without claiming a concurrent UI snapshot or live profile-swap protocol.
   Restoring controls preserves musical histories and the generator clock.
5. The existing `Engine` interface and the present 47 parameters/state4 are a
   compatibility boundary. Adding spectral source research is possible without
   changing those meanings or taking active ScannerLineFoh, M6 FOH, R4,
   named-library/browser or native MIDI-retirement paths.

These are source observations. No build, functional test, benchmark, physical
measurement, hosted job or remote publication was executed by this assignment.

## Recommended independent continuation

### Primary recommendation: prepared harmonic source research

Implement an additive, separately identified M2 **terminal-voltage harmonic
source evaluator**, based on pages 69-72, with an explicit unmeasured fixture
profile and a deterministic offline comparison. Keep the existing sine bank and
nominal dry Engine as the unchanged baseline unless a later reviewed integration
contract explicitly selects the new mode. This supplies a useful missing sound
primitive while the other active sessions own their scanner/crossover/rotary
and native adapter gates.

The first bounded contract should declare:

- Stable source IDs and reuse of one source result per sample across all routes.
- Terminal-voltage coefficient basis, real-output conjugate symmetry or an
  equivalent real sine/cosine basis, phase origin and normalized-amplitude units.
- An explicit maximum harmonic count, finite input admission, immutable
  value-owned prepared coefficients, sample-rate/Nyquist margin and bounded
  memory/processing work.
- Whether the module owns phase or consumes a source phase snapshot. Do not
  create two independent phase owners for one physical source.
- Rejected preparation leaves the existing state unchanged; note/control events
  cannot reset phases. Rate changes retain phase and recompute band limits under
  a stated lifecycle policy.
- A declared source boundary preventing duplicate generator-filter application.
  Physical flux models, once-per-revolution asymmetry and inferred coil/gap data
  remain separate later work.

Acceptance should include a one-harmonic analytic comparator against the sine
baseline, independent multi-harmonic summation, spectral rejection above the
chosen margin, phase continuity through silent/disconnected processing, all
supported rate transitions, block partition equivalence, invalid-input
transactionality and allocation observation. Synthetic coefficient fixtures
establish arithmetic and runtime behavior; they do not qualify a real pickup.

### Secondary recommendation: sparse coherent leakage primitive

If a second independently owned module is preferable, pages 81-84 already give a
complete first numerical boundary: a finite, bounded gain-only directed graph
between source-terminal arrays, with unique source/destination identities,
explicit gain/phase convention and no post-contact injection by default. Begin
outside Engine with independent sparse-versus-dense comparisons, zero-edge
identity, single-edge destination isolation, negative-gain polarity, coefficient
bounds and strict malformed-profile rejection. Retain immutable metadata with
the authoring profile. Do not fabricate a factory adjacency graph or a measured
leakage amount; any audition profile must be labeled a proposed extension.

The harmonic module is the stronger first step because it directly advances the
current ideal-sine limitation and later supports measured waveform ingestion.
Leakage fitting needs more care about overlapping frequencies, identifiability
and injection boundaries.
