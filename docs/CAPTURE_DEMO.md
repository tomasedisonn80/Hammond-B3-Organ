# Original synthetic capture demo

This is the frozen project-proposed **capture-demo-v1** generator contract.
It defines a small original software fixture for the existing [capture
v1](CAPTURE_FORMAT.md), [corpus](CAPTURE_CORPUS_CONTRACT.md),
[policy](CAPTURE_COMPARISON_CONTRACT.md), [job](CAPTURE_JOB_CONTRACT.md) and
[study](CAPTURE_STUDY.md) contracts. It is engineering demonstration material,
not an acquired instrument corpus, an independently sealed study, a cached
execution report or physical evidence. Implementation and independent acceptance
are recorded separately in the current session ledger.

## API, dependencies and creation behavior

Python 3.10 or newer and its standard library are sufficient. The generator
imports no test helper or capture-tool module, performs no analysis, and needs
no package installation, network, native SDK or audio device.

```python
class DemoError(ValueError): ...

build_demo(output_dir: str | pathlib.Path) -> dict
main(argv: list[str] | None = None) -> int
```

`output_dir` must be an exact nonempty string or a `pathlib.Path` instance.
Bytes, other path-like objects and string subclasses are rejected. Unicode
paths and absolute or current-directory-relative paths are supported. The
parent directory must already exist. Ordinary aliases in ancestors are allowed;
the selected output leaf must not exist, including as a dangling symlink.

The complete fixed payload is prepared in memory before creating the selected
directory. Create that directory exclusively, then create the two fixed child
directories and every file exclusively. Never overwrite, merge into, empty or
remove an existing destination. No recursive parent creation or recursive
cleanup is allowed. If any operation fails after the new root is created,
raise `DemoError` explicitly disclosing that partial new creation is retained
at the requested location. Preserve it for caller inspection; do not guess
which files are safe to remove. Cancellation propagates and likewise leaves
any created directory intact. The creation sequence is not an atomic
multi-file transaction or a sandbox against adversarial concurrent mutation.

Success returns a fresh deterministic inventory with exactly:

| Key | Value |
| --- | --- |
| `schema_version` | Integer `1`. |
| `contract_origin` | `project-proposed-capture-demo-v1`. |
| `evidence_class` | `synthetic_numerical_fixture`. |
| `execution` | `not_run`: building inputs does not execute an audit/job/study. |
| `file_count` | Integer `16`. |
| `total_size_bytes` | Sum of all sixteen complete payload lengths. |
| `files` | All sixteen rows sorted by ASCII relative path; each has exactly `path`, `size_bytes`, `sha256` for the generated bytes. |
| `physical_fidelity` | `not_established`. |
| `permissions` | `not_established`. |

The inventory does not contain its own digest, an output location, a timestamp,
a hostname, a runtime observation or an execution verdict. The archive and
inventory bytes are deterministic across output locations and supported Python
platforms. Report bytes from subsequently executed tools have their own
runtime/source identity rules; they are not frozen by this generator.

The only CLI write option is one required, nonempty `--output`. Abbreviated,
duplicate and unknown options are usage errors. `--help` exits 0 without
creation; usage errors exit 2; `DemoError` exits 1 with `demo error: ...` on
stderr and no success inventory. Successful creation exits 0 and emits the
inventory as sorted two-space-indented UTF-8 JSON with one final LF, independently
of terminal text encoding and newline translation. A text-only in-process
stdout such as `io.StringIO` receives the equivalent Unicode string. If stdout
publication fails after creation, report that the created archive is retained;
already written stdout bytes cannot be retracted. No report is saved implicitly.

## Exact generated archive

Only the following sixteen files and the `corpus/` and `corpus/audio/`
subdirectories are created below the new root. JSON is serialized with
`json.dumps(value, sort_keys=True, indent=2, ensure_ascii=False, allow_nan=False)`
plus one LF. Text files use explicit UTF-8/LF. Binary streams have no headers.

| Path | Purpose |
| --- | --- |
| `README.md` | Portable instructions, fixture provenance and all expected exits. |
| `EXPECTED.json` | Literal independent numerical/hash expectations; explicitly `execution: "not_run"`. |
| `corpus/corpus.json` | One original-byte-bound validation-purpose corpus. |
| `corpus/reference.json` | Recorded synthetic metadata for the literal reference. |
| `corpus/quarter.json` | Recorded synthetic metadata for the quarter-offset vector. |
| `corpus/half.json` | Recorded synthetic metadata for the half-offset vector. |
| `corpus/audio/reference.f32` | Sixteen little-endian float32 bytes. |
| `corpus/audio/quarter.f32` | Sixteen little-endian float32 bytes. |
| `corpus/audio/half.f32` | Sixteen little-endian float32 bytes. |
| `policy-pass.json` | Fixed RMS bound 0.375 FS, synthetic margin 0.125 FS. |
| `policy-inconclusive.json` | Fixed RMS bound 0.25 FS, synthetic margin 0.125 FS. |
| `policy-fail.json` | Fixed RMS bound 0.25 FS, synthetic margin 0.125 FS. |
| `job-pass.json` | Reference versus quarter offset; expected pass. |
| `job-inconclusive.json` | Reference versus quarter offset; expected inconclusive. |
| `job-fail.json` | Reference versus half offset; expected failed. |
| `study.json` | All three jobs in pass, inconclusive, fail order; expected failed. |

Jobs use `corpus/corpus.json` relative to their own root and the corresponding
root-level policy. The corpus uses manifest names relative to `corpus/`; each
manifest uses `audio/<name>.f32` relative to its own parent. The study binds
each root-level job's original bytes. Every SHA-256 reference is computed from
the exact bytes that are written, including original JSON whitespace/newline;
no pathname is resolved against the execution working directory. No output
file is an analysis report. The inventory is returned, not stored as a
seventeenth file.

## Original vectors and literal expected results

All streams use declared rate **4 Hz**, **one channel**, **four frames** and
little-endian IEEE-754 float32 samples. These are mathematical test coordinates,
not a measured clock or an audio-quality recording. Values greater than one
are intentional finite numerical samples, with no hardware clipping claim.

| Capture | Literal samples | Original bytes in hexadecimal |
| --- | --- | --- |
| `reference` | `[1, -1, 1, -1]` | `0000803f000080bf0000803f000080bf` |
| `quarter` | `[1.25, -0.75, 1.25, -0.75]` | `0000a03f000040bf0000a03f000040bf` |
| `half` | `[1.5, -0.5, 1.5, -0.5]` | `0000c03f000000bf0000c03f000000bf` |

These raw and decoded identities are the literal independent vectors frozen in
[job contract section 8](CAPTURE_JOB_CONTRACT.md#8-independent-acceptance-and-later-work).
They must be retained as constants in `EXPECTED.json`, never obtained from a
producer report and presented as an independent oracle.

| `quarter` | `bac1c395abe23908b8c106a28b6c151bc25b9473d470f4d942775b5dfdf523e2` | `79d8014af588d583abcc570598d3e073413543ef518b339cbca37dbb5eb6bd0c` |

The decoded digest version is `hammond-capture-decoded-v1`. Its independent
preimage is the literal 27-byte `b"HAMMOND-CAPTURE-DECODED-V1\x00"`, followed
by `struct.pack("<IIQ", 4, 1, 4)` and the four frame-major binary64 samples.

All jobs select `[0,4)` on each side, rectangular window, `floor_fs: 1e-12`,
frequency list `[1]`, `pairing: "index"` and `transform: "none"`. The only
decision criterion is channel-zero `rms_error_fs`. The frequency is retained
for demonstration but is not a policy target; no exact cross-platform spectral
bit pattern is promised. The independent pointwise values and interval rule are:

| Job ID / file | Candidate | Bias, RMS and maximum error (FS) | Bound (FS) | Margin (FS) | Interval (FS) | Status / CLI exit |
| --- | --- | ---: | ---: | ---: | --- | --- |
| `demo-pass` / `job-pass.json` | `quarter` | 0.25 | 0.375 | 0.125 | [0.125, 0.375] | `pass` / 0 |
| `demo-inconclusive` / `job-inconclusive.json` | `quarter` | 0.25 | 0.25 | 0.125 | [0.125, 0.375] | `inconclusive` / 3 |
| `demo-fail` / `job-fail.json` | `half` | 0.5 | 0.25 | 0.125 | [0.375, 0.625] | `failed` / 1 |

`EXPECTED.json` retains these explicit values, each vector's raw hexadecimal
bytes, samples and literal hashes, and the study expectation. The study ID is
`synthetic-offset-demo`; its ordered IDs are `demo-pass`, `demo-inconclusive`,
`demo-fail`. It must retain all three complete reports and return **`failed`,
exit 1**, with one pass, one inconclusive and one failed job. Its declared work
is twelve window samples and twelve spectral terms; all three roles are
`validation`. An overall failure is the intended successful demonstration of
failure retention, not an instruction to relax a policy. The corpus itself
is expected to pass its full file/audio audit within its engineering scope.

## Constructed metadata and evidence boundary

All capture, corpus, job, policy, session, group, channel and operator identifiers
are constructed software-fixture labels. None names a physical specimen,
human acquisition operator or historical capture. Every capture is explicitly
`capture_kind: "synthetic"`; `recorded` means that its generated bytes are
actually retained. The required acquisition timestamp is the fixed placeholder
`2000-01-01T00:00:00Z`, explicitly disclosed in each manifest as constructed
metadata, not an observed acquisition, generation or file-creation time.

All three captures share `synthetic-demo-session` and
`synthetic-demo-related`; their common family label is `literal-offsets`.
They belong to one related group, with corpus purpose `validation` and v1 role
`held_out`. That label demonstrates a role mapping; it establishes no untouched
holdout, independent recording or physical sampling protocol. The corpus ID
is `synthetic-offset-corpus`. There are no derived or support files and no
asserted external capture parents.

Specimen identity is null with an explicit synthetic reason. The channel
boundary is `synthetic`; physical scale and clock calibration are
`not_applicable` with explicit reasons. The signal path has no physical device,
probe, microphone, amplifier, recorder or load. Rights remain null with an
explicit reason: original arithmetic fixture construction supplies no
instrument/third-party permission evidence or project-wide licensing clearance.
Each manifest discloses every identity/date/rights placeholder as constructed.

Policies use `evidence_class: "synthetic_numerical_fixture"`,
`evaluation_role: "validation"` and the literal decision margin above with
`basis: "synthetic_numerical"`. The margin is chosen only to demonstrate
the interval rule; it is not a physical measurement uncertainty, confidence
level or atlas fidelity tolerance. Policy `freeze_evidence` remains unknown:
fixed bytes do not prove independently retained creation chronology or
preregistration. All physical and permission claims remain `not_established`
in inventories, expectations and actual tool reports.

## Running and continuing

From a repository checkout, use a new location whose parent already exists:

```sh
python3 tools/make_capture_demo.py --output /existing/parent/new-demo
python3 tools/capture_corpus.py --input /existing/parent/new-demo/corpus/corpus.json --check-files --check-audio
python3 tools/capture_job.py --input /existing/parent/new-demo/job-pass.json
python3 tools/capture_job.py --input /existing/parent/new-demo/job-inconclusive.json
python3 tools/capture_job.py --input /existing/parent/new-demo/job-fail.json
python3 tools/capture_study.py --input /existing/parent/new-demo/study.json
```

The expected exits are respectively **0, 0, 0, 3, 1, 1**. Run each command
separately or use a harness that records those expected nonzero outcomes.
Do not chain them using an unconditional success-only shell gate. The checked-in
`examples/capture-demo/` is already created: run its jobs directly or generate
a fresh archive elsewhere; rebuilding into that existing directory must fail.
An absolute tool path supports a foreign working directory. Moving the complete
archive preserves every declared locator and identity.

Retain fresh reports through each tool's explicit new-file output option, or
through caller-chosen stdout capture, when execution evidence is needed.
Inspect their observed runtime/source hashes and complete failed/inconclusive
rows. `EXPECTED.json` and a generation inventory are never execution evidence.
Independent acceptance must compare against literal expectations and unchanged
original files, check byte-identical relocation/regeneration, existing-destination
preservation and disclosed partial creation, and run the actual job/study tools
only after their implementation is ready. Physical acquisition, calibrated
uncertainty, fitting, listening and device/host qualification remain later gates.
