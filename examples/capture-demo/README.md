# Original synthetic capture demo

This archive contains sixteen deterministic input/expectation files, including
three actual sixteen-byte raw float32 streams. It is an original software
fixture. No Hammond, Leslie, recorder, audio device, native SDK, network or
third-party Python package is involved. It is not an instrument acquisition,
a cached execution report, a physical corpus or permission evidence.

## Fixed inputs and expected outcomes

Every stream has declared rate 4 Hz, one channel and four frames:

| Capture | Literal samples |
| --- | --- |
| reference | [1, -1, 1, -1] |
| quarter | [1.25, -0.75, 1.25, -0.75] |
| half | [1.5, -0.5, 1.5, -0.5] |

The greater-than-one samples are intentional finite mathematical values, not
a claim about physical converter clipping. The binary format is headerless
little-endian float32. These are raw synthetic inputs, with no derived files.

All jobs select frames [0,4) with index pairing, no transform, a rectangular
window, floor 1e-12 FS and selected frequency [1] Hz. Their only policy target
is the channel-zero RMS error, with synthetic decision margin 0.125 FS.

| Job | Error (FS) | Bound (FS) | Decision interval (FS) | Expected status | Exit |
| --- | ---: | ---: | --- | --- | ---: |
| [job-pass.json](job-pass.json) | 0.25 | 0.375 | [0.125, 0.375] | pass | 0 |
| [job-inconclusive.json](job-inconclusive.json) | 0.25 | 0.25 | [0.125, 0.375] | inconclusive | 3 |
| [job-fail.json](job-fail.json) | 0.5 | 0.25 | [0.375, 0.625] | failed | 1 |

The bias and maximum absolute error equal the listed RMS error exactly.
[EXPECTED.json](EXPECTED.json) retains independent literal expected values,
original hexadecimal bytes, raw SHA-256 values and canonical decoded hashes
from the frozen job contract. Its execution field is not_run: expected values
are an oracle, never an observed report. The generator also returns an inventory
with execution:not_run; creating files performs no audit or comparison.

[study.json](study.json) retains all three jobs in pass, inconclusive, fail
order. Its expected overall status is **failed**, exit **1**, with exactly one
pass, one inconclusive and one failed result. All roles are validation. The
declared work totals twelve window samples and twelve spectral terms. Preserve
these deliberate outcomes; do not loosen the bounds to make every exit zero.

## Constructed metadata and rights

All capture/corpus/job/policy/session/group/channel/operator identifiers are
constructed fixture labels, not hardware identities or human acquisition
operators. Every capture is explicitly synthetic. Recorded status means only
that generated bytes are retained. The required timestamp
2000-01-01T00:00:00Z is a fixed constructed metadata placeholder, not an observed
acquisition, generation or file-creation time; each manifest discloses this.

All three captures share synthetic-demo-session, synthetic-demo-related and
the literal-offsets family label. They form one related validation-purpose
group with v1 held_out roles. Those roles do not prove independence, unused
holdout material, an actual session or an acquisition protocol. Specimen
identity is unknown, the boundary is synthetic, and physical scale/clock
calibration is explicitly not applicable. No physical signal path or load is
asserted. The shared nominal rate does not measure a clock.

Rights remain unknown in every manifest. These original arithmetic fixtures
provide no instrument/third-party permission evidence or project-wide licensing
clearance. A rights reason is a disclosure, not a permission grant. The fixed
policies retain unknown freeze evidence: hashes do not authenticate chronology
or preregistration. Their margin is chosen only to demonstrate the numerical
interval rule, not physical uncertainty, confidence coverage or a fidelity
tolerance. All physical and permission claims remain not_established.

## Run actual tools

Python 3.10 or newer is sufficient. From a Hammond-B3-Organ repository checkout,
run each of these separately for the checked-in example:

```sh
python3 tools/capture_corpus.py --input examples/capture-demo/corpus/corpus.json --check-files --check-audio
python3 tools/capture_job.py --input examples/capture-demo/job-pass.json
python3 tools/capture_job.py --input examples/capture-demo/job-inconclusive.json
python3 tools/capture_job.py --input examples/capture-demo/job-fail.json
python3 tools/capture_study.py --input examples/capture-demo/study.json
```

Expected exits are respectively 0, 0, 3, 1, 1. A completed failed result has a
full JSON report and empty stderr; a rejected input instead has an error and
no report. Keep each complete report, including failed/inconclusive rows, when
recording execution. Reports identify actual tool-source and runtime bytes;
no report is shipped in this archive. The full corpus audit is expected to
pass its declared byte/audio/group checks without establishing physical facts.

For a relocated archive, replace examples/capture-demo with its new location;
an absolute tool path works from a foreign working directory. Move the whole
archive together. All internal paths are relative to their declared roots.
Changing any bytes requires reviewing the original-byte hash bindings.

Create another identical archive with:

```sh
python3 tools/make_capture_demo.py --output /existing/parent/new-demo
```

The parent must exist and new-demo must not. The generator never overwrites,
merges or recursively removes destinations. A later write failure leaves the
partially created new directory for inspection and explicitly reports that
fact. The checked-in directory already exists: use a new destination. The
returned inventory is not saved as another archive file.
